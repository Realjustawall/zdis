# Security changes and remaining limits

- New accounts and conversations no longer cause the server to generate and escrow private E2EE identities. New clients generate nonextractable private keys in Web Crypto and retain them in per-account IndexedDB. Unowned legacy browser identities are left untouched for explicit recovery rather than assigned to the next account that logs in. A recipient must initialize their client identity before receiving new encrypted messages. Device-to-device key transfer/recovery is not implemented in this change; a new device cannot decrypt the previous device's history automatically.
- Existing escrow records remain readable by their authenticated account for backward compatibility. Historical messages encrypted to those keys are **not** protected from a server operator who has the database and application secret. Removing historical escrow requires a separate, deliberate device migration with a recovery plan; deleting it automatically could destroy access to message history. Historical migration tooling still supports the legacy escrow format.
- Account creation commits independently of private-key provisioning; a key provisioning error can no longer leave an account created while reporting failure. Duplicate account races return HTTP 409 after a transactional rollback. Browser tests exercise creation and immediate listing.
- Platform accounts are admin/member. Existing creator accounts migrate to member. Legacy creator input is accepted by the admin API only as an unprivileged member alias. Staff/developer/streamer badges and custom platform roles no longer grant platform privileges. Group-scoped roles and permissions remain separate.
- WebSocket upgrades validate Origin as well as the authenticated session. Forced-password-change, disabled, suspended and banned accounts cannot establish a socket. Every incoming packet rechecks account/session state. Session revocation also immediately disconnects affected sockets across the Socket.IO adapter, including idle receiving sockets. Revoking one session preserves other valid sessions.
- Presence is hydrated in `ready`, updates avatars, member lists and counts live, and is restored after reconnection. User profile changes and account creation notify connected clients. Existing message, channel, group and notification events continue to push through Socket.IO; writes/snapshots use authenticated HTTP APIs.
- Production dependency audit was clean after upgrading body-parser, multer, nodemailer and Zod. This is an advisory database check, not a proof of absence of vulnerabilities.

This change is not a full cryptographic audit. There is no absolute-security claim: legacy escrow, public-key directory trust, device compromise, metadata visibility and the absence of a ratcheting/multi-device protocol remain material limitations. Review migrations and back up the deployment before applying changes.
